# [0.2.2] - 2026-02-12

## Added

### Checklist Enhancements
- **New checklist item types**: Added `security` as a valid checklist item type
- **New layers**: Added `integration` and `security` as valid implementation layers
- **NFR tracking**: Added `nfr_refs` field to checklist items for linking Non-Functional Requirements
- **Fixture reference**: Added `fixture_ref` field to checklist items for test fixture tracking
- **Ambiguity resolution**: Added `decision` and `resolved` fields to track how ambiguities are resolved

### Evidence Tracking
- **New evidence type**: Added `reference` as a valid evidence type
- **Evidence path**: Added `path` field to evidence for file reference
- **Evidence section**: Added `section` field to evidence for specific documentation sections

### Implementation Planning
- **NFR measurement methods**: Added `nfr_measurement_methods` field to define how NFRs will be measured
- **Timeout constants**: Added `timeout_constants` field to define timeout configurations for tests

### Validation
- **New validation rules**: Enhanced checklist validation to enforce required fields for non-deferred items
- **Type validation**: Added validation for new checklist types and layers
- **Fixture validation**: Added validation for fixture references
- **NFR validation**: Added validation for NFR references

### Testing
- **New test cases**: Added comprehensive tests for new validation rules
- **Invalid fixture tests**: Added tests for missing NFR refs, missing fixture refs, invalid types, and invalid layers
- **Valid fixture tests**: Added tests for minimal and full fixtures with new fields

## Changed

### Prompts
- Updated prompts to reflect new checklist types, layers, and fields
- Enhanced evidence tracking to include reference type
- Improved ambiguity resolution tracking

### Schema
- Updated schema to include new fields and validation rules
- Added new enum values for types and layers
- Enhanced validation requirements for checklist items

## Validation Rules

### Checklist Items
- Non-deferred checklist items must have `nfr_refs` and `fixture_ref`
- Checklist items must use valid types: `behavior`, `constraint`, `validation`, `metadata`, `perf`, `logging`, `docs`, `security`
- Checklist items must use valid layers: `db`, `model`, `service`, `api`, `integration`, `tests`, `docs`, `config`, `security`

### Evidence
- Evidence must use valid types: `log`, `snippet`, `screenshot`, `reference`
- Reference evidence must include `path` and `section` fields

## Migration Notes

This release introduces new checklist tracking capabilities and validation rules. Projects using Step 16 will need to ensure their implementation plans include the new fields:

- `nfr_refs` for non-deferred checklist items
- `fixture_ref` for non-deferred checklist items
- `decision` and `resolved` for ambiguity tracking
- `reference` type evidence with `path` and `section` fields

The validation rules are enforced by `specdev_tools/validate.py` and will reject invalid implementations during the validation phase.
