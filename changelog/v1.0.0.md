## [1.0.0]

Foundational release of the DevSpec AI Toolkit — a schema-first pipeline
that turns product specs into machine-checkable JSON artifacts and drives
AI-assisted implementation against them.

### Added

**Spec Pipeline**
- Phase 0 seed authority — `spec/common/seed_manifest.json` routes project
  context to pipeline steps; no seed paths are hardcoded in prompts
- Forward-only waterfall — spec steps 00 (Charter) through 16, including
  sub-steps 02a and 13a, each emitting a JSON artifact validated against a
  strict schema (`additionalProperties: false`)
- Per-milestone Trinity loop (16a Plan → 16b Code → 16c Review), tracked by
  a scope/drift ledger at `spec/16_impl_context.json`

**CLI (`specdev`)**

Key commands — full reference at `docs/developers/reference.md`.

- `specdev spec-check` — unified gate running schema, canonical, hallucination,
  traceability, and seed/fixture validators in one pass
- `specdev guide <code>` — inline remediation playbooks (ships E110 and E530,
  including E530 subcode variants)
- `specdev canon-accept` — promote project vocabulary proposals to the
  canonical registry
- `specdev json` family — surgical read/edit primitives for spec artifacts
  (`read`, `read-multi`, `patch`, `insert`, `delete`) and inspection
  subcommands (`keys`, `structure`, `schema`, `resolve-pointers`)
- `specdev governance-check` — commit message validation against Step 10 rules
- `specdev align` — migration tooling for upgrading host specs across toolkit
  versions *(experimental)*
- Diagnostics and utilities: `specdev env-check`, `specdev upstream-backlog`,
  `specdev prompt-context`

**Validation**
- Validators and linters covering schema compliance, canonical integrity,
  traceability closure, hallucination detection, vague-language detection,
  forward-replay staleness, and cross-artifact consistency
- Structured error output — errors carry `code` and `message`, plus
  `subcode`, `file`, `jq_path`, and `value` where applicable, in `--json` mode
- Auto-generated remediation candidates for selected canonical and
  hallucination errors (E110, E530 subcodes)
- W→E promotion — promote warning codes to errors via
  `SPECDEV_WARNINGS_AS_ERRORS` or `SPECDEV_PROMOTE_CODES`

**Canonical Registry**
- Toolkit-tier canonical registry (`canon/`) defining core vocabulary kinds
  under `cn:core:`; project terms promoted to `cn:project:` via `canon-accept`
- Alias resolution with sunset enforcement (E125)
- 11 registered trace types enforced across all artifacts

**AI Agent Protocol**
- Two-phase agent flow (Clarify → Emit) with a Self-Audit Gate
- Machine-readable agent manifest (`docs/agents/manifest.json`) — two-phase
  default with per-step mode overrides
- 16 shared prompt expectations inherited by all step prompts

**Claude Code Skills**
- `specdev-context` — fundamental skill for all pipeline work; loads step
  context and applies surgical edits via `specdev json` primitives
- `specdev-step`, `specdev-review`, `specdev-trinity` — agentified authoring,
  review, and Trinity orchestration *(experimental)*
- `devspec_pr_audit` — six-phase PR audit for toolkit-internal changes
  *(experimental)*

**Project Bootstrap**
- `scripts/init_project.py` — initializes a host repo with submodule, spec
  directory structure, virtualenv, pre-commit hooks, and CI workflow
