## [1.1.1]

### Breaking Changes

- `schema/14_roadmap.schema.json` roadmap task `status` enum now accepts `deferred`
  and `wont_do` alongside `pending`/`in_progress`/`done`, each requiring a new
  task-level `status_reason` field. Milestones gained the equivalent
  `milestone_status_reason` field, required when a milestone's `status` is
  `deferred`. Remediation: for a task that should be paused or permanently
  cancelled instead of deleted, set `status` to `deferred` or `wont_do` and
  author a `status_reason` naming the blocker and, for `deferred`, the condition
  required to resume; for a deferred milestone, author a
  `milestone_status_reason` with the same content.

- `schema/16_impl_context.schema.json` checklist items now require their own
  `deferred_reason` when `checklist_status == "deferred"` (previously only
  enforced at the whole-plan level). Remediation: populate `deferred_reason` on
  each deferred checklist item, naming the blocker and the condition required to
  undefer.

### Added

- Added `"wont_do"` `checklist_status` to `schema/16_impl_context.schema.json`,
  requiring a `wont_do_reason` field. `wont_do` items receive the same treatment
  as `deferred` items throughout the pipeline: roadmap/checklist coverage
  (E304/E307/W576), proof-of-work exemptions, `milestone_ref` requirement (W581),
  the planned-vs-executed diff (E305), `spec_ref.id` requirement (E590), and
  milestone phase-position roll-up.

- Added W616 `PAUSED_OR_CANCELLED_ITEM_MARKED_VERIFIED` to `step_16.py`: fires
  when a checklist item is `checklist_status` deferred/wont_do while
  `implementation.status` still says `"verified"`. Advisory only, non-promotable.

- Added E536 `CONTRADICTORY_OUT_OF_SCOPE_FR_FIXTURE` to `traceability_closure.py`:
  fires when an FR is listed in Step 08's fixture `out_of_scope[]` but is also
  referenced by a fixture's `targets[]`.

- Added W555 `STEP00_SEED_OUT_OF_SCOPE_THIN` to `seed_lint.py`: fires when seeds
  routed to step "00" supply fewer than 3 substantive out-of-scope items
  combined. Warn-only, non-promotable.

- `specdev upstream-backlog` now also scans `plan.ambiguities[]` (16a,
  planning-phase) alongside `execution.emergent_ambiguities[]` (16b/16c). Each
  record carries an `origin` field (`"plan"` or `"execution"`); the 16a binary
  blocking/non_blocking severity maps onto the shared low/medium/high/critical
  rank for `--severity` filtering and sort order.

- Added W617 `UPSTREAM_BACKLOG_STATUS_FILTERED`: fires when `specdev
  upstream-backlog`'s `--status` filter (default `open`) excludes at least one
  record that otherwise satisfies the `--severity` threshold. JSON output gains
  `summary.hidden_by_status_count`. Informational only, non-promotable.

- Added a W595 `SEED_UNTRACKED` sub-reason: seed drift detection now
  cross-references the seed manifest against the seed index and flags manifest
  seeds missing from the index as untracked.

- `prompt_11_redteam.md`'s mitigation-coverage requirement now applies to every
  threat regardless of severity (previously only high-severity threats required
  a mitigation).

- `prompt_14_roadmap.md` now requires a milestone's task-level `fr_refs` to
  collectively cover every FR listed in that milestone's own `fr_refs`
  (previously stated that `fr_refs`/`capability_refs` belong only on
  milestones, not tasks).

- `changelog_parser.py`'s `validate_changelog`/`load_version` now accept
  `version: "unreleased"` (resolving to `changelog/unreleased.yaml`); a new
  check emits E520 when a changelog's `source_of_truth`/`render_target` path
  is missing, not a file, or empty.

- `prompt_16_impl_context.md` now documents the E308 FR-release workflow: a
  deferred milestone still owns every FR/API in its `fr_refs` (no automatic
  release), so reassigning an FR requires explicitly removing its ID from the
  deferred milestone's `fr_refs`.

### Changed

- Relaxed the `vc:core:canon` `entries.minItems` constraint from 1 to 0, so a
  freshly-bootstrapped empty project-canon registry no longer fails
  `spec-check`/`canonical-integrity`.

- Extended `changelog/format.yaml` `optional_fields` with `source_of_truth` and
  `render_target` keys.

- `schema/16_impl_context.schema.json`'s `fixture_ref` proof-requirement now
  applies only to proof-types (behavior/constraint/validation/perf/security),
  not every non-deferred checklist item — metadata/docs/logging items are
  exempt. `nfr_refs` was removed from the schema requirement entirely; it is
  now enforced only at the validator level (see the `nfr_refs` fix above).

### Fixed

- `W565 UNCOVERED_FR_FIXTURE` is now exempted by a new `out_of_scope[]` array in
  `schema/08_fixtures.schema.json` (`fr_id` + `rationale`), independent from
  Step 05's API `out_of_scope[]` list. `step_08.py` validates each
  `out_of_scope[].fr_id` against an existing `04_fr_list.json` entry (E590).

- `E304 ROADMAP_TASK_UNCOVERED` no longer excludes deferred/wont_do checklist
  items from counting as coverage for their roadmap task; the milestone-status
  fallback now also skips deferred milestones alongside done/completed, and a
  roadmap task's own deferred/wont_do status is honored directly.

- `E307 BEHAVIOR_VALIDATION_PAIRING` no longer excludes deferred checklist items
  when grouping items by `spec_ref.id` to check for a behavior+validation pair.

- `W576 TASK_EXECUTION_MISSING` now recognizes a roadmap task as paused or
  cancelled: skips tasks with status deferred/wont_do, and (as
  defense-in-depth) tasks whose covering checklist items are all
  deferred/wont_do.

- `W568 UNCOVERED_CAPABILITY` now exempts capabilities with `scope:"out"` or
  `scope:"future"`.

- `matrix.py`'s `build_trace_matrix` now unconditionally excludes
  `priority:"wont-have"` FRs and `out_of_scope[]` FRs (Step-05 API and Step-08
  fixture out_of_scope sets, each with its own `fr_total`/`fr_total_fixture`
  denominator) from its coverage ratios, not just when
  `SPECDEV_MATRIX_STRICT=1` enforces the threshold as fatal.

- `step_11.py`'s `W583 API_UNCOVERED_BY_THREAT` and `W615
  INVARIANT_UNEXERCISED_BY_THREAT` no longer demand threat coverage for an
  API/invariant whose only tracing FR is `priority:"wont-have"`.

- `cli.py`'s `completeness-check` command now excludes parked entities
  (wont-have FRs, Step-05/Step-08 out_of_scope FRs, `scope:"out"`/
  `scope:"future"` capabilities) from its `total_frs`/`total_caps`
  denominators, split per exemption set.

- `linked_test_expectation` is no longer unconditionally required on every Step
  16 checklist item — required only when `checklist_status` is `"active"`.

- Generated pre-commit hook configuration now invokes `devspec_env/bin/python`
  (not the ambient `python`) for every hook entry point, honoring a custom
  `--venv-name` instead of hardcoding `devspec_env`. The `validate-all` hook
  is renamed to `spec-check` and passes `--spec-root ./spec --git-root .`;
  the `seed-lint`, `canonical-integrity`, and `prompt-sync` hooks receive the
  same flags where applicable. Each hook's `files:` match pattern now also
  substitutes the bare `devspec_toolkit/` path (not just the `./devspec_toolkit`
  form used in flag args), so hooks generated for a non-default submodule path
  actually trigger on their target files.

- Generated `devspec-governance` commit-msg hook now sets
  `pass_filenames: true`, so `governance-check --message` receives the
  commit-message file.

- Generated host CI workflow now runs `spec-check` (with project-canon flags)
  instead of `validate-all`.

- Corrected submodule-deployment docs and prompt-contract examples to pass
  project-canon flags on spec-validating commands, and switched CI-gates/
  scaffold examples to `spec-check`.

- `step_16.py` no longer crashes with an `AttributeError` when a Step 16
  artifact's top-level `plan` field is not a dict; treated as an empty plan
  instead. This includes `_collect_milestone_refs` (used by the E304
  roadmap-coverage check and by `step_16c.py`), which independently re-read
  the raw `plan` field without the same guard.

- `specdev upstream-backlog` now skips a Trinity Anchor misfiled inside
  `impl_context/` instead of misreading its `plan.ambiguities[]` under the
  wrong severity scale.

- Registry entry-key scanning (`generate.py`, `entry_key_registry.py`,
  `matrix.py`, `registry_check.py`, `json_utils.py`) now recurses to arbitrary
  nesting depth instead of one level, so 3+-deep nested arrays (e.g. roadmap
  `milestones[].tasks[].acceptance_criteria`) are correctly tracked.
  `registry_check.py` no longer treats a missing nested array as drift — only a
  present-but-wrong-shape one — since nested arrays may be legitimately
  optional. Run `specdev registry-generate` to refresh
  `tools/entry_key_registry.json` (byte-identical unless your schemas define
  deeper nesting).

- `nfr_refs` is no longer schema-required on proof-type Step 16 checklist
  items; the validator now requires it only when the item's owning FR has at
  least one direct trace in `07_nfrs.json`, and skips the gate entirely when
  `07_nfrs.json` is absent.

- `W601 EVIDENCE_NO_ARTIFACT_REF`'s artifact-reference check (evidence must
  cite a spec artifact ID) now fires only for proof-type checklist items,
  matching the existing proof-type exemption.

- `E541 UNBOUND_CANONICAL_TERM`'s structural suppression is now
  namespace-aware: an object is suppressed only when none of its `*_ref`/
  `*_refs` slots can bind the fired term's kind, rather than whenever it has
  no ref slot at all — fixing false positives on objects like `nfrs[]`,
  `capabilities[]`, and roadmap `milestones[]` that carry unrelated ref slots.
  Added `patternProperties` support to the child-schema lookup, plus four
  key-based skips (`03_glossary.json` `definition`; `ambiguities`;
  `docs_impact`; `review_requirements`). `execution` is skipped
  unconditionally rather than namespace-aware, since its schema leaves
  `additionalProperties` open.

- `specdev align status` no longer recommends migration when a project's
  version is ahead of the toolkit's (a downgrade). It now reports that the
  project is ahead and no migration is needed, instead of falling through to
  "update required".

- `specdev align diff`/`status`/`update` no longer mis-maps Step 16, which
  ships two schemas but only one root spec file: the Trinity Anchor at
  `spec/16_impl_context.json` is now diffed against `vc:16-anchor` (was
  spuriously flagged NEEDS UPDATE / MISSING); the per-milestone
  `vc:16-impl-context` schema is correctly not treated as a root step.

- `prompts/migration/template_fixtures.md` no longer documents two schema
  anti-patterns as correct usage: fixture `targets[]` entries now specify
  `type` as the target's canonical kind (`fr`/`api`/`nfr`/`invariant`, with the
  validates relationship in `note`) rather than `type: validates`, and
  `tag_ref`'s documented kind is corrected from `term` to `tag`.

- `prompt_16b_impl_coder.md`'s STOP condition and coverage-closure checks
  corrected to use valid `implementation.status`/`checklist_status` values
  (previously instructed setting a non-existent `status: blocked`; now sets
  `implementation.status: deferred` and logs an `emergent_ambiguity` with its
  own `blocked` status).

- `prompt_08_fixtures.md`'s valid `targets[]` ID prefix guidance narrowed to
  Step 08's actual accepted set (fr/api/nfr/inv), replacing a reference to the
  full cross-step `traceRef` prefix vocabulary that includes prefixes Step 08
  does not accept.

- `prompt_16a_impl_planner.md`'s `plan.docs`/`docs_impact` authority
  corrected: `plan.docs_impact.docs_touched` (not `plan.docs`) is what 16b
  reads for its file list; `plan.docs.required_updates` is advisory-only with
  no validator consumer.
