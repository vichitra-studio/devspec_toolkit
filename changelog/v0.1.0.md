# v0.1.0 - 2026-01-14

## Initial Release

Baseline version establishing the DevSpec Toolkit and migration tracking infrastructure.

---

## What's Included

### Spec Discovery (Steps 00-12)

A complete discovery workflow that transforms product vision into machine-checkable specifications:

| Step | Purpose |
|------|---------|
| 00 | **Charter** — Project vision, stakeholders, success metrics |
| 01 | **Capabilities** — High-level feature groupings |
| 02 | **System Sketch** — Architecture and component boundaries |
| 03 | **Glossary** — Ubiquitous language definitions |
| 04 | **FR List** — Functional requirements with acceptance criteria |
| 05 | **Interface Contracts** — API signatures and data structures |
| 06 | **Invariants** — Business rules that must always hold |
| 07 | **NFRs** — Non-functional requirements with measurable targets |
| 08 | **Fixtures** — Test data and expected behaviors |
| 09 | **Implementation Plan** — Technical approach and dependencies |
| 10 | **Governance** — Commit message and change control rules |
| 11 | **Redteam** — Security and failure mode analysis |
| 12 | **CI Gates** — Continuous integration quality checks |

### Extension & Planning (Steps 13-14)

| Step | Purpose |
|------|---------|
| 13 | **Extension Generator** — Discovers domain-specific spec needs |
| 14 | **Roadmap** — Atomic user stories with tasks and milestones |

### Implementation (Steps 15-16)

| Step | Purpose |
|------|---------|
| 15 | **Scaffold** — Project structure generation guidance |
| 16 | **Trinity Loop** — Planner (16a), Coder (16b), Reviewer (16c) |

## CLI Tools

```bash
specdev validate <file>           # Validate single spec against schema
specdev validate-all <spec_dir>   # Validate all specs in directory
specdev matrix <spec_dir>         # Generate FR ↔ Interface ↔ Fixture trace matrix
specdev fixtures-lint <spec_dir>  # Check fixture coverage and consistency
specdev invariants-check <dir>    # Validate invariant rules against sample data
specdev governance-check <dir>    # Validate commit message against governance rules
specdev ai-help [--step NN]       # Quick reference for AI interaction workflow
```

---

## Key Features

- **Schema-first**: Every spec step has a JSON Schema ensuring structural validity
- **AI-assisted**: Prompt library with deterministic two-phase (Clarify → Emit) pattern
- **Traceable**: FR ↔ Interface ↔ Fixture links maintained via `trace_refs`
- **Linted early**: Pre-commit hooks and CI workflows catch issues at commit time
- **Bootstrappable**: `init_project.py` sets up projects with submodule, hooks, and CI

---

## Migration Notes

This is the baseline from which all future migrations are measured. Projects created with v0.1.0 can use the `specdev align` command (when released) to detect and apply changes from future versions.
